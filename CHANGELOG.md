# Changelog

## 2026-11-27 — Milestone 24: data-quality results table + history
- New `lakehouse.quality.results`: `quality.results` (one row per check result, all
  families, normalised to pass / warn / fail / skipped, with observed value and full
  JSON details) and `quality.check_runs`; transactional `record()`
- History queries: `latest()` with failure streaks and last-pass time, filtered
  `history()`, `runs()` and `pass_rate_by_day()`
- CLI: `--record` on `lakehouse dq`, `freshness` and `anomalies`; new
  `lakehouse checks run|latest|history|runs|trend`
- Docs: `docs/dq-results.md`; tests in `tests/test_dq_results.py`

## 2026-11-26 — Milestone 23: row-count anomaly detection (z-score on daily volumes)
- New `lakehouse.quality.anomalies`: z-score of a day's count against a trailing window
  that excludes the day itself, missing days counted as 0, high/low anomalies,
  `insufficient_history`, flat-baseline handling and an optional same-weekday
  (seasonal) baseline
- Series: `ingestion:<source>` (records ingested per day) and `events:<silver table>`
  (crimes by occurrence, 311 by creation, taxi trips by start date)
- CLI: `lakehouse anomalies [SERIES...] [--days N] [--window W] [--threshold Z]
  [--seasonal] [--json]`, exit status 1 on any anomaly
- Docs: `docs/anomalies.md`; tests in `tests/test_anomalies.py`

## 2026-11-25 — Milestone 22: freshness checks per source
- New `lakehouse.quality.freshness`: per source an **ingestion** check (time since the
  last run) and an optional **data** check (age of the newest record, from the watermark),
  each graded ok / warn / error; never-ingested sources and unparseable watermarks are errors
- `FreshnessPolicy` in `SourceConfig`, set per source under `freshness:` in
  `config/sources.yaml` (validated on load); data checks for crimes (240/480 h) and 311
  (48/120 h), ingestion-only for the historical taxi and Urbana datasets
- CLI: `lakehouse freshness [SOURCE...] [--fail-on warn|error] [--json]`
- Docs: `docs/freshness.md`; tests in `tests/test_freshness.py`

## 2026-11-24 — Milestone 21: expectation framework (not-null, unique, range, accepted values)
- New `lakehouse.quality.expectations`: `NotNull`, `Unique` (multi-column), `InRange`
  (numbers, dates, timestamps; either bound optional) and `AcceptedValues`, each compiled
  to one parameterised SQL query; failing-row counts, failing share, sample of offending
  values, `mostly` tolerance; SQL errors are recorded as failures
- New `lakehouse.quality.suites`: suites for the three silver tables and both reference
  tables; missing tables are skipped
- CLI: `lakehouse dq [TABLE...] [--json]`, exit status 1 on any failure
- Docs: `docs/data-quality.md`; tests in `tests/test_expectations.py`

## 2026-11-23 — Milestone 20: data dictionary for silver tables (Phase 2 complete)
- New `docs/data-dictionary.md`, generated by `lakehouse.silver.dictionary`: every column
  of `silver.crimes`, `silver.service_requests` and `silver.taxi_trips` with its real
  type (read from empty builds incl. geo columns), origin (raw field + kind, derived,
  lineage, geo) and description; grain and quality checks per table; reference tables
- Descriptions added for derived (`DERIVED_DESCRIPTIONS`), lineage
  (`LINEAGE_DESCRIPTIONS`) and geo (`GEO_COLUMN_DESCRIPTIONS`) columns, plus a `GRAIN`
  per table; an undocumented column is an error
- CLI: `lakehouse docs dictionary [--out PATH] [--check]`; CI and a test fail when the
  committed dictionary is stale
- Tests in `tests/test_data_dictionary.py`

## 2026-11-22 — Milestone 19: unit tests for every silver transform
- New `tests/test_silver_contracts.py`: one `TableCase` per silver table and contract
  tests run against all of them (schema and types, column-spec hygiene, one row per key
  across bronze versions, empty/missing/sparse/garbage input, idempotence,
  incremental = full, quality checks, registry and geo wiring); a completeness test fails
  if a registered silver build has no case
- Edge-case matrices for every typing kind; the last uncovered branches (non-numeric
  GeoJSON area property, incremental build without a changes relation) now tested
- Silver package at 100 % line coverage; CI runs pytest with coverage and gates the
  silver package at >= 95 % (`pytest-cov` added to dev dependencies)
- Docs: `docs/testing.md`

## 2026-11-21 — Milestone 18: incremental silver builds
- `build_typed_table(incremental=True, changes_relation=...)`: recomputes only keys with
  bronze rows ingested after the table's watermark and upserts them in one transaction;
  results match a full rebuild
- New `silver._watermarks` (high-water mark + column-spec hash); automatic full build when
  the table or watermark is missing or the spec changed (`BuildResult.full_reason`)
- `BuildResult.mode` / `processed`; `silver._build_log` records both; cast failures cover
  processed rows, quality counts cover the whole table
- Silver builders take `incremental=`; the transform runner is incremental by default,
  `lakehouse silver --full-refresh` forces a rebuild; geo columns survive upserts
- Fixed the sample output in `docs/silver-framework.md`
- Docs: `docs/silver-incremental.md`; tests in `tests/test_silver_incremental.py`

## 2026-11-20 — Milestone 17: silver transform framework (registry + dependency ordering)
- New `lakehouse.silver.registry`: `Transform` (name, run, depends_on), `Registry` with
  validation, cycle detection, deterministic topological `plan()` (downstream by default,
  optional upstream) and `run()` returning per-step status, duration and result
- Missing inputs (`MissingInputError`) are skips, not failures; a failed step skips only
  its dependents while other branches continue
- Default registry: `reference_seeds`, `crimes`, `service_requests`, `taxi_trips` and
  their `*_geo` steps, so geo cleanup re-runs automatically after a rebuild
- CLI: `lakehouse silver [TRANSFORM...] [--list] [--upstream] [--no-downstream]
  [--areas FILE]`; `lakehouse silver crimes` keeps working
- Docs: `docs/silver-framework.md`; tests in `tests/test_silver_registry.py`

## 2026-11-19 — Milestone 16: SCD Type 2 helper for slowly-changing reference data
- New `lakehouse.scd.apply_scd2`: merges a keyed source into a history table with
  `valid_from` / `valid_to` / `is_current` / `version` / `row_hash`; handles new,
  changed, unchanged, removed (`close_missing`) and reappearing keys; idempotent,
  transactional, forward-only, validates one non-NULL row per key
- `as_of_sql` helper for point-in-time queries
- `lakehouse seed` now maintains `reference.<seed>_history` for every loaded seed and
  reports the changes it recorded
- README project layout fixed (`seeds/` was listed inside `src/lakehouse/`)
- Docs: `docs/scd2.md`; tests in `tests/test_scd.py`

## 2026-11-18 — Milestone 15: shared reference data (seed CSVs)
- New `seeds/community_areas.csv` (77 official community areas) and
  `seeds/police_districts.csv` (22 current CPD districts)
- New `lakehouse.reference`: declarative `SEEDS` (types, key, key range, expected rows);

- Docs: `docs/reference-data.md` (incl. provenance caveats); tests in `tests/test_reference.py`

## 2026-11-17 — Milestone 14: geospatial cleanup (lat/long validation, community-area lookup)
- New `lakehouse.silver.geo`: per-point `geo_status` (ok, missing, null_island, swapped,
  out_of_range, outside_chicago) against a padded Chicago bounding box, with
  `latitude_clean` / `longitude_clean` (swapped pairs corrected)
- Community-area lookup from a user-supplied GeoJSON (Polygon/MultiPolygon with holes),
  pure-Python point-in-polygon: `community_area_geo`, `community_area_mismatch`,
  `community_area_resolved` (reported value preferred, geometry fills gaps)
- Works on `silver.crimes`, `silver.service_requests` and `silver.taxi_trips`
  (pickup_/dropoff_ prefixes); idempotent; counts logged and returned
- CLI: `lakehouse geo <table> [--areas FILE] [--area-property NAME]`
- Docs: `docs/geo-cleanup.md`; tests in `tests/test_geo.py` (synthetic boundaries)

## 2026-11-16 — Milestone 13: silver taxi trips (fares, durations, outlier flags)

- CLI: `lakehouse silver taxi_trips`; synthetic fixture `tests/fixtures/chicago_taxi_sample.json`
- Docs: `docs/silver-taxi.md`; tests in `tests/test_silver_taxi.py`

## 2026-11-11 — Milestone 8: rate-limit handling (HTTP 429, Retry-After)
- `SocrataClient` treats HTTP 429 (and 503 with `Retry-After`) as rate limits: waits as
  long as `Retry-After` asks (seconds or HTTP date), else exponential backoff
- Separate budgets: `max_rate_limit_retries` (default 5) vs. `max_retries` for other errors;
  waits above `max_retry_after` (default 300 s) raise `RateLimitError` instead of sleeping
- `parse_retry_after`, `RateLimitError`, per-client `RequestStats` (requests, retries,
  rate_limited, waited_s); structured WARNING log per wait; injectable `sleep`
- Docs: `docs/rate-limits.md`; tests in `tests/test_rate_limit.py`

## 2026-11-10 — Milestone 7: Parquet export of bronze (partitioned by ingest date)
- New `lakehouse.storage.export`: `export_source` / `export_all` write bronze tables (or
  their `__latest` views) as Hive-partitioned Parquet (`ingest_date=YYYY-MM-DD/`) via
  DuckDB `COPY`, with per-partition row counts; `read_export` queries them back
- Exports rewrite the source directory, so they are idempotent and drop stale partitions
- CLI: `lakehouse export [source] [--latest] [--out DIR]`
- Docs: `docs/parquet-export.md`; tests in `tests/test_export.py`

## 2026-11-05 — Milestone 5: schema-drift detection between runs
- New `lakehouse.drift`: `compare(old, new)` → `DriftReport` of added/removed fields, type
  widening/narrowing/incompatible changes and nullability, each graded info/warning/breaking
  (tuned for Socrata, which omits null keys and returns small incremental samples)
- `BronzeStore.write` compares each new snapshot with the previous one, logs drift at the
  matching level and stores changes in `bronze._schema_drift`; `last_drift`, `drift_history`
- CLI: `lakehouse drift <source> [--from RUN --to RUN] [--json] [--history] [--fail-on SEV]`
  and `lakehouse ingest --fail-on-drift SEV` (exit status 2, data still lands)
- Docs: `docs/schema-drift.md`; tests in `tests/test_drift.py`

## 2026-11-04 — Milestone 4: schema snapshot per run
- New `lakehouse.schema`: streaming `SchemaInferrer` with JSON vs. inferred types (integer,
  number, boolean, date, timestamp from Socrata strings), type widening, nullability,
  and a shape fingerprint; leading-zero codes like `"018"` stay strings
- `BronzeStore.write` captures a snapshot per non-empty run into `bronze._schema_snapshots`
  (same single pass, keyed by `run_id`); `schema_history` / `schema_snapshot` to read them
- CLI: `lakehouse schema <source> [--run-id ID] [--json] [--history]`
- Docs: `docs/schema-snapshots.md`; tests in `tests/test_schema.py`
